1//! A CoAP security for embedded devices, supporting OSCORE/EDHOC and managing credentials.
2//!
3//! The crate is under heavy development: Its API is in flux. So far, it has hidden dependencies on a
4//! particular implementation of the [`coap-message`] provided (it needs to be a
5//! [`coap_message_implementations::inmemory_write::Message`]).
6//!
7//! # Logging
8//!
9//! Extensive logging is available in this crate through [`defmt_or_log`], depending on features
10//! enabled.
11//!
12//! Errors from CoAP are currently logged through its [`Debug2Format`](defmt_or_log::Debug2Format)
13//! facility, representing a compromise between development and runtime complexity. Should
14//! benchmarks show this to be a significant factor in code size in applications that need error
15//! handling, more fine grained control can be implemented (eg. offering an option to make
16//! Debug2Format merely print the type name or even make it empty).
17//!
18//! This crate mainly logs on the trace, debug and error level; the latter provides details when an
19//! error is sent over the network and the details are not visible to the peer.
20//!
21//! See the book for [how defmt is configured in
22//! Ariel OS](https://ariel-os.github.io/ariel-os/dev/docs/book/tooling/defmt.html).
23//!
24//! **Warning**: At the Debug level, this module may show cryptographic key material. This will be
25//! revised once all components have been interop-tested.
